1. PROJECT IDENTITY & PRODUCT DIRECTION
--------------------------------------------------------------------------------

  Repository:
    https://github.com/PHinterbauer/TdoT-WebGL

  Default branch:
    main

  Project:
    A self-contained, offline-capable Three.js/WebGL inspection experience for
    NIGHTFALL, the Armored Core associated with the original Raven in
    Armored Core VI: Fires of Rubicon.

  Current concept:
    NIGHTFALL is displayed inside a compact industrial maintenance hangar.
    The AC is suspended from a workshop gantry / overhead crane using a
    four-point sling. The viewer can orbit the camera and inspect selected
    components through numbered 3D hotspots or a component list.

    Selecting a component opens a dossier containing:
      - Component / system designation
      - Manufacturer or in-universe manufacturer attribution
      - Component category
      - Technical description
      - Technical record / selected statistics
      - Armored Core VI gameplay or lore context
      - Notes about regulation, interpretation, or source limitations

  The experience should feel like a professional in-universe maintenance
  terminal or technical museum exhibit, not a generic game HUD.

  Visual direction:
    - Industrial, utilitarian, believable workshop / hangar.
    - Dark muted steel, concrete, weathered surfaces, timber details.
    - Restrained amber / warm task lighting and small safety-orange accents.
    - NIGHTFALL remains the visual focus.
    - High-quality composition, readable model silhouette, controlled contrast.
    - Background detail should support the model, not compete with it.
    - UI should be compact, precise, legible, and consistent with the scene.

  Do not revert to:
    - The former open-air / mountain / flying backdrop.
    - A visible sky or horizon flight environment.
    - The former dash / forward-lean animation.
    - Procedural exhaust or thruster flames.
    - The former time-of-day sunlight slider.
    - A generic animation-control dashboard.


2. FILE STRUCTURE & RUNTIME CONSTRAINTS
--------------------------------------------------------------------------------

  Current repository root:
    index.html
      The complete browser runtime. Contains the HTML, CSS, embedded
      Three.js r128 build, embedded matching GLTFLoader r128, application
      JavaScript, scene construction, UI, controls, and inspection data.

    raven.glb
      The user-provided NIGHTFALL GLB model. This is the primary visual asset.
      Preserve the original binary file unless explicitly asked to replace it.

    README.md
      Public project overview, quick start, controls, and high-level features.

    PROJECT_INFO.txt
      This technical handover document.

    LICENSE
      Repository license information.

  Runtime architecture is intentionally single-file:
    - index.html is the only HTML / JavaScript runtime source file.
    - raven.glb is the adjacent 3D model asset.
    - Do not create app.js, style.css, separate loader files, package files,
      build tooling, or other runtime dependencies unless the owner explicitly
      changes this requirement.
    - Do not add external script imports, CDNs, remote fonts, APIs, or network
      dependencies. The application must remain usable offline.
    - CSS belongs in the existing <style> block in index.html.
    - Application JavaScript belongs in the existing inline application script.
    - The bundled Three.js and GLTFLoader code must not be modified casually.

  The repository currently uses three inline script blocks:
    1. Three.js r128 library.
    2. Matching GLTFLoader r128 implementation.
    3. Application code, enclosed in an IIFE with strict mode.

  Keep the runtime compatible with modern Chromium browsers (Chrome / Edge).
  Avoid relying on a build step, npm, Node.js, or a local development server.


3. HOW TO RUN THE PROJECT
--------------------------------------------------------------------------------

  Local Windows folder used by the owner:
    C:\Users\phint\Documents\WebGL Render

  Local update command:
    cd "C:\Users\phint\Documents\WebGL Render"
    git pull origin main

  Direct local launch:
    1. Keep index.html and raven.glb in the same folder.
    2. Double-click index.html.
    3. The browser displays a local-file dialog.
    4. Select raven.glb from the same folder.
    5. The browser reads the chosen File object with FileReader and passes its
       ArrayBuffer to the embedded GLTFLoader.parse() method.

  The explicit file selection is intentional. Browsers restrict file:// pages
  from reading adjacent files by pathname. Do not remove the file picker or
  replace it with an unsafe local-file path assumption.

  Hosted launch:
    - When served over HTTP(S), CONFIG.modelPath is './raven.glb'.
    - GLTFLoader loads the adjacent model automatically.
    - The page does not need an API, backend, build step, or package manager.

  The sidebar's "Replace GLB" action opens the same local file picker so a
  different .glb can be loaded without refreshing the page.

5. 3D SCENE: WORKSHOP / HANGAR
--------------------------------------------------------------------------------

  The workshop is generated procedurally in createBackdrop() and attached to
  hangarRoot. It does not use an external environment model or image.

  Current visual elements:
    - Textured concrete floor.
    - Dark industrial side walls and rear wall.
    - Corrugated wall ribs / vertical metal strips.
    - Rear roller-door structure and horizontal panels.
    - Exposed roof ridge, sloped roof trusses, and cross beams.
    - Overhead crane rails and travelling trolley / crossbeam.
    - Service benches, storage cabinets, drawers, and salvage / parts crates.
    - Small practical workshop lamps with warm point lights.
    - Painted amber safety perimeter around the inspection bay.
    - Low-density floating dust particles.

  Lighting:
    - Procedural studio reflection environment is still created by
      createStudioEnvironment().
    - Ambient and hemisphere fill lights.
    - Warm directional key light with shadow mapping.
    - Cool / neutral fill light.
    - Warm rim light.
    - Renderer uses antialiasing, ACES filmic tone mapping, and sRGB output.
    - Pixel ratio is capped at 2 to avoid excessive GPU cost on high-DPI displays.

  Current scene scale is expressed in abstract Three.js world units.
  The workshop shell is deliberately larger than the AC and the camera is
  framed around the suspended model.

  Keep the model well lit and readable. Do not allow the walls, floor, crane,
  dust, or task lights to overwhelm the AC. Prefer restrained visual detail
  over clutter.

  Procedural materials and geometries should be reused where sensible. Avoid
  creating new per-frame objects or materials in animate().


6. MODEL LOADING, NORMALIZATION & TRANSFORMS
--------------------------------------------------------------------------------

  Model file:
    raven.glb

  Loader:
    Embedded THREE.GLTFLoader matching Three.js r128.

  Loading paths:
    - file:// : local file picker -> FileReader.readAsArrayBuffer() ->
      GLTFLoader.parse().
    - HTTP(S): GLTFLoader.load('./raven.glb').

  handleModelLoaded(gltf, sourceName) currently:
    1. Validates gltf.scene.
    2. Traverses imported meshes.
    3. Enables castShadow and receiveShadow.
    4. Disables frustumCulled for imported meshes to prevent individual parts
       from disappearing when imported bounds / transforms are unreliable.
    5. Calculates the model's Box3 bounds, center, and largest dimension.
    6. Scales the model uniformly so its largest dimension is 9 world units.
    7. Offsets the model so its bounding-box center is at its local origin.
    8. Wraps the normalized model in mechGroup.
    9. Places mechGroup at approximately (0, 5.1, -0.65).
    10. Applies a small Y rotation for the intended display angle.
    11. Creates inspection anchors and the suspension rig.
    12. Updates the loading status and recenters the camera.

  Do not casually change the model normalization or top-level transform:
    Inspection anchors, cable endpoints, and initial camera framing depend on
    these coordinate conventions.

  When replacing the model or changing its scale:
    - Recalculate the bounding box after normalization.
    - Re-check all inspection anchors.
    - Re-check cable attachment positions.
    - Re-check hotspot visibility and the camera framing.
    - Do not assume another GLB uses the same orientation, scale, or pivot.

  Model replacement cleanup:
    clearCurrentModel() removes the previous mech group, clears hotspot DOM
    elements and anchor maps, and disposes the suspension rig. Preserve this
    cleanup behavior when extending model reload functionality.


7. SUSPENSION / CRANE SYSTEM
--------------------------------------------------------------------------------

  The former dash animation is replaced by a restrained suspended inspection
  motion. NIGHTFALL should look heavy and secured, not like it is flying.

  Scene hierarchy and roles:
    - hangarRoot contains the workshop.
    - craneAssembly is the overhead gantry / trolley assembly.
    - suspensionSpreader is a separate group beneath the trolley.
    - suspensionCables are four dynamically oriented cylinder meshes.
    - mechGroup contains the normalized GLB plus the four visible clamp groups.

  The spreader is separate from craneAssembly so that cable start points remain
  attached to the same moving crossbar rather than to the entire crane rails.

  Four cable endpoints and four clamp points are currently derived from
  normalized model bounds using the ratios in createSuspensionRig(bounds).
  The points are approximate and are not bound to semantic GLB node names.

  updateSuspensionRig():
    - Converts each cable's start point from suspensionSpreader local space to
      world space.
    - Converts its end point from mechGroup local space to world space.
    - Positions and rotates each cylinder between those two points.
    - Updates cable length.

  updateAnimation(dt):
    - Applies a very small rotation on X and Z to mechGroup.
    - Applies a very small vertical bob.
    - Applies a subtle Z displacement to craneAssembly.
    - Uses state.motionEnabled to hold the system stationary or enable motion.

  UI:
    - "Hold Position" toggles the sway off.
    - "Resume Sway" enables it again.

  Avoid large amplitudes or fast oscillations. Keep the four cables visually
  taut and connected for the complete animation cycle.


8. INTERACTIVE COMPONENT INSPECTION
--------------------------------------------------------------------------------

  The component index is defined in the INSPECTION_PARTS array near the top of
  the application code. It currently contains nine records:

    ID           Displayed part / system
    ------------ -----------------------------------------------
    head         HC-2000/BC SHADE EYE
    core         CC-2000 ORBITER
    arms         AC-2000 TOOL ARM
    legs         2C-2000 CRAWLER
    right-arm    RF-025 SCUDDER
    left-arm     PB-033M ASHMEAD
    right-back   SONGBIRDS
    left-back    BML-G1/P32DUO-03
    internal     BST-G1/P10 booster, FC-006 ABBOT FCS,
                 DF-GN-02 LING-TAI generator

  Each record contains:
    - id: stable identifier used by UI and hotspot mapping
    - n: displayed two-digit marker number
    - label: short component name in the index
    - system: technical slot / system heading
    - part: part designation
    - maker: manufacturer attribution
    - category: component category
    - a: normalized local-space anchor ratio [x, y, z]
    - description: technical description
    - intel: game/lore context
    - facts: compact technical facts / selected statistics
    - note: caveat, source context, or extra explanation

  UI behavior:
    - renderComponentIndex() creates sidebar buttons from INSPECTION_PARTS.
    - createInspectionAnchors(bounds) converts normalized anchor ratios into
      local-space coordinates within the normalized model bounding box.
    - The function creates numbered DOM buttons in #hotspot-layer.
    - updateInspectionHotspots() projects each local anchor through mechGroup
      and camera into screen coordinates.
    - selectInspectionPart(id) updates the active list button, marker, index,
      and information panel.
    - A user can select a part from the index or click its projected marker.
    - pickInspectionPart(x, y) raycasts against the model, then selects the
      nearest configured inspection anchor to the ray hit point.

  Important limitation:
    Inspection anchors are currently heuristic points derived from normalized
    bounding-box ratios. They are NOT yet attached to exact GLB mesh nodes,
    material groups, or named part objects. Clicking model geometry identifies
    the nearest configured anchor, which is an approximation.

    The actual GLB hierarchy has not yet been inspected and mapped to all nine
    semantic components. Hotspot placement must be visually calibrated against
    the real model in a browser. If the GLB contains useful node names or
    separate meshes, a future improvement should map the inspection points to
    actual nodes and use those nodes' world transforms / bounding boxes.

  The "internal" system is not a distinct visible external mesh component. It
  represents internal performance systems as a grouped dossier entry.

10. CAMERA, POINTER & VIEWPORT CONTROLS
--------------------------------------------------------------------------------

  Current interaction:
    - Left mouse drag: orbit around the inspection target.
    - Middle mouse drag: pan / shift the viewing target.
    - Right mouse drag: also pans; context menu is suppressed on the canvas.
    - Mouse wheel: zoom.
    - One-finger touch drag: orbit.
    - A short left click on the canvas: selects the nearest model inspection
      anchor through raycasting.
    - Clicking a numbered hotspot or component list entry selects that part.
    - Recenter View restores the initial camera parameters.
    - Collapse Panel hides the left dossier.
    - The persistent open-panel icon restores it.
    - Fullscreen is available through the panel and floating top-right control.

  Camera state:
    - theta: azimuth
    - phi: polar angle
    - radius: camera distance
    - target: camera look-at point

  Current camera defaults:
    - theta = PI * 0.25
    - phi = PI * 0.39
    - radius = 19
    - target = (1.4, 5.05, -0.4)

  Limits:
    - phi is clamped away from the poles.
    - Pan target X: approximately -3.4 to 3.4.
    - Pan target Y: approximately 2.4 to 7.7.
    - Pan target Z: approximately -2.8 to 2.5.
    - Camera radius: approximately 11.5 to 34.

  Keep the mech discoverable and framed. Do not allow the pan / zoom limits to
  send the object irretrievably off-screen. Recenter View must remain reliable
  after model replacement, camera rotation, pan, and zoom.

  If changing pointer handling, preserve the distinction between a click and a
  drag so rotating the camera does not accidentally select a component.

12. KNOWN LIMITATIONS & OPEN TECHNICAL WORK
--------------------------------------------------------------------------------

  Confirmed limitations:
    1. No browser visual QA has yet been completed after the latest hangar
       implementation with the owner's exact raven.glb file.
    2. Inspection anchors are based on normalized bounding-box ratios rather
       than actual GLB part nodes. Their screen positions need visual review.
    3. Four suspension clamp / cable attachment points are also based on
       normalized bounding-box ratios. Their exact physical attachment points
       need calibration against the actual model.
    4. The pickInspectionPart() method raycasts the model but maps the hit to
       the nearest configured anchor; it does not yet identify the actual
       semantic mesh or subassembly under the pointer.
    5. Some values / in-game details in INSPECTION_PARTS require source and
       regulation verification before being treated as authoritative.
    6. The placeholder AC is only a basic fallback. It is not a substitute
       for the supplied NIGHTFALL model.
    7. The project keeps some legacy helper code from earlier iterations
       inside index.html. Do not assume that every remaining function or
       variable related to flames, time-of-day lighting, or dash controls is
       part of the active UI or active render pipeline.

  Suggested next development tasks (priority order):
    P0 — Visual validation with the real GLB:
      - Load raven.glb in Chrome / Edge.
      - Check framing and the visual relationship between mech, hangar, crane,
        cables, and four clamps.
      - Confirm the model is not clipped or too dark.
      - Confirm the hangar has a convincing depth / scale and does not compete
        with the AC.
      - Adjust camera and suspension heights if needed.

    P1 — Correct model-aware inspection anchors:
      - Inspect the GLB node hierarchy (names, types, mesh counts, bounds).
      - Identify actual head, core, arms, legs, hand weapons, shoulder weapons,
        and internal-system representative nodes where possible.
      - Prefer named nodes / actual mesh groups over fixed bounding ratios.
      - Build a robust fallback when a particular GLB has merged meshes.
      - Keep normalized anchor mapping as a fallback, not as the primary path.
      - Verify all nine hotspots from multiple camera angles.

    P2 — Calibrate the suspension rig:
      - Place each clamp at believable load-bearing hardpoints.
      - Ensure the sling spreader, hoist, cables, clamps, and AC all meet.
      - Cables must remain attached during the tiny sway animation.
      - Check cable depth, visibility, thickness, and shadows.
      - Avoid placing clamps on weapon barrels, antennae, or fragile protrusions.

    P3 — Improve direct selection:
      - Where the GLB has separate meshes, map mesh / ancestor node references
        to part IDs and select the actual component under the cursor.
      - Highlight the selected part subtly (outline, emissive accent, or
        restrained callout) without permanently changing original materials.
      - Ensure click selection and hotspot selection remain synchronized.

    P4 — Content quality:
      - Verify all frame and weapon designations for the exact NIGHTFALL loadout.
      - Verify manufacturers, internal systems, part statistics, and regulation.
      - Add trustworthy sources or in-game references to technical records.
      - Separate canon, game mechanics, build interpretation, and narrative intel.

    P5 — Professional polish:
      - Add subtle camera focus / selection feedback.
      - Consider a small component callout line between hotspot and model.
      - Improve workshop material variation and local shadowing.
      - Optimize render cost without reducing model clarity.
      - Add keyboard accessibility and clear focus states to all UI controls.

  These are candidate tasks, not claims that the work has already been done.
